# Data Set

The project is tested on two kinds of volumes:

1. **Real scans:** medical NRRD files from the 3D Slicer sample data. They show that the program works on real data, with real sizes and data types.
2. **Synthetic volumes:** small volumes generated by code, where we know in advance what every cut must look like. They are used to check correctness.

## Real scans

| Name | What it is | Size (x × y × z) | Voxel type | File size | Why it is in the set |
| --- | --- | --- | --- | --- | --- |
| MRHead | MRI of a head | 256 × 256 × 130 | int16 | 6.6 MB | Recommended by the assignment. Small, fast to test. |
| MRBrainTumor1 | MRI of a brain with a tumor | 256 × 256 × 112 | int16 | 4.9 MB | A second MRI with different axes and a clear structure (the tumor) to look for. |
| CTChest | CT of a chest | 512 × 512 × 139 | int32 | 41 MB | A different scanner type (CT), 32-bit values, and negative values (air ≈ −1000). |
| CTACardio | CT angiography of the heart | 512 × 512 × 321 | int16 | 62 MB | The largest real volume (~84M voxels), close to the 500³ size of the performance requirement. |

Download them (they are not stored in git because of their size):

```
python data/download_data.py              # all four (~115 MB)
python data/download_data.py MRHead       # only one
```

Each file is checked against its SHA256 checksum after download.
Source: [3D Slicer sample data](https://github.com/Slicer/SlicerTestingData/releases).

**Note:** these real files use *signed* integers (int16 / int32), while the assignment speaks of unsigned values. The program therefore accepts both (see SRS FR-2).

## Synthetic volumes

| File | Size | Voxel type | Content | What a correct cut looks like |
| --- | --- | --- | --- | --- |
| `synthetic_cube.nrrd` | 64³ | uint8 | A bright cube (200) in the middle of a black volume | A bright shape on black; a cut parallel to a face is a square. |
| `synthetic_gradient.nrrd` | 64³ | uint16 | Value = 1000 · x | A cut at constant x is one flat value; a cut along x brightens evenly. |
| `synthetic_sphere.nrrd` | 64³ | uint32 | A ball of radius 21.3 (value 100000) | Any cut through the centre is a circle of the same size, at any angle. |
| `synthetic_odd_shape.nrrd` | 10 × 40 × 25 | uint8 | Different values in 4 corners | Catches mixed-up axes (x, y, z) and wrong orientation. |

They are small (a few KB), so they are stored in git. To regenerate them:

```
python data/make_synthetic.py
```

Together the set covers all three bit sizes (8, 16, 32), signed and unsigned types, cubic and non-cubic sizes, and sizes from 10 to 512 per axis.

The 500³ volume for the performance test (NFR-1) is generated in memory by the benchmark, not stored as a file (it would be 125 MB).
